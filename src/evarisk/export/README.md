# export

Назначение: выгрузка сохранённого расчёта в читаемом и машиночитаемом виде из одного объекта `AssessmentResult`.

## Интерфейс
- `bundle.build_zip(result, briefing=None) -> bytes`: архив с `result.json` (ровно `result.model_dump_json(indent=1)`), `report.md`, `briefing.md`, `sources.json` (список `Provenance` из `bundle.sources_of`), `timeline.csv` (`line,start,end,level,kind,rule`). Сводка берётся сохранённая (`briefing.load_cached`), а без неё собирается шаблонная из тех же фактов. Факты сводки в `briefing.md` называют минуты high и critical и минуты без уровня по линиям (`_per_line`: «sep_protons 74 мин, meteor_showers 0 мин», D84); у сводок до D84 минут по линиям нет, и сумма идёт с пометкой «(сумма по линиям)».
- `bundle.render_briefing(briefing) -> str`: текст сводки для экипажа, происхождение текста («сформулировано языковой моделью по фактам расчёта, числа проверены автоматически» или «шаблон: модель недоступна»), перечень фактов с минутами и отрезками, список разрешённых значений, провенанс и речевой вариант текста.
- `bundle.sources_of(result) -> list[Provenance]`: `result.sources_used` плюс провенанс интервалов `verification.predicted` и `verification.observed` и оснований бейзлайнов `verification.baselines`, по одному на `raw_id`. Отчёт ссылается на `raw_id` сверки, а наблюдения факта опубликованы позже отсечения и в `sources_used` не входят; в разделе «Источники» такая запись помечена «только в проверке после события, в расчёт и рекомендацию не входит».
- `bundle.render_report(result) -> str`: отчёт Markdown с режимом, моментом данных, версией алгоритма, отсечением для replay, рекомендацией и правилами, траекторией, интервалами каждой линии с источниками, таблицей окон, источниками и ограничениями. В replay раздел «Проверка после события» содержит таблицу «Сравнение с простыми подходами»: наш расчёт и три бейзлайна с выбранным окном, минутами экспозиции по факту в нём, попаданиями, пропусками и ложными тревогами по минутам экспозиции, заблаговременностью и устойчивостью окна (D66), та же, что на странице.
- Эндпоинт `GET /assessments/{id}/export` в `api/app.py` отдаёт архив как `application/zip`.

- В разделе «Рекомендация» отчёта сначала объяснение обычными словами списком (`Recommendation.explanation`, D76; строки по линиям «Протоны: в запрошенном окне 4 ч 42 мин, …» вложены под фразой с двоеточием, их находит `_PER_LINE` по названиям линий из `windows.explain.LINE_NAMES`, D78), затем «Технические подробности: » с `reason` и правила; у расчёта до D76 объяснения нет и остаётся только технический текст.
- Раздел «Проверка после события» говорит, что факт это тот же расчёт с теми же правилами по всем данным, доступным сегодня, включая опубликованные позже отсечения, а не независимые наблюдения: ошибки самих правил такая проверка не покажет (D78).

## Инварианты
- `result.json` в архиве это тот же объект `AssessmentResult`, что возвращает API (`model_dump_json(indent=1)`): поля и значения совпадают, отличаются только отступы.
- Отчёт содержит версию алгоритма, отсечение для replay и каждый `raw_id`; каждый `raw_id` отчёта есть в `sources.json` (`tests/e2e/test_replay_verification.py::test_every_raw_id_of_the_report_is_listed_in_sources`).
- Модуль не читает хранилище и ничего не пересчитывает: только сохранённый результат и сводку по нему.

## Как тестировать
- `uv run pytest tests/e2e/test_replay_verification.py -q -k baseline`: таблица бейзлайнов в `report.md` и их провенанс в `sources.json`.
- `uv run pytest tests/unit/test_export.py -q`; фикстура `tests/fixtures/assessments/review_2024-05-10.json` это реальный ответ `POST /assessments` на данных фикстур 10 мая 2024.

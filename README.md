# evarisk: внешние риски ВКД на МКС

Команда MISIS GO, КосмоХакатон 2026, трек «Прогнозирование внешних рисков и планирование ВКД на МКС».

Космонавты МКС иногда выходят в открытый космос, это внекорабельная деятельность (ВКД). Во время выхода экипажу
угрожают солнечные протоны и метеорные потоки. Наш сервис помогает выбрать время выхода: оставить его, перенести
(куда и почему) или честно сказать, что оснований для выбора нет.

Аналитик задаёт начало и длительность выхода и период, в котором выход можно сдвинуть. Остальное сервис делает сам:
забирает открытые данные NOAA, NASA, GFZ и CelesTrak и поминутно считает трассу станции. Каждое число в ответе ведёт
к сырой записи источника, её можно открыть и скачать. Допуск к ВКД мы не выдаём и дозу человека не считаем. Сервис
показывает внешние факторы и их основания, а решает руководитель работ.

## Главные понятия

Эти слова встречаются на странице и в документах. Время в примерах указано в UTC.

| понятие | что значит |
|---|---|
| окно | время выхода, например 04:00–10:00 |
| период допустимого начала | когда выход может начаться: промежуток от 15 минут до 24 часов |
| линия риска | один фактор риска с поминутным уровнем: протоны, метеоры, сближения, освещённость |
| уровни | `none` спокойно, `elevated` повышенный, `high` высокий, `critical` критический, `unknown` нет данных |
| опасные минуты | минуты `high` и `critical`; по ним окна сравниваются в первую очередь |
| повышенный фон | минуты `elevated`: обстановка выше спокойной, но до экипажа опасное не доходит |
| геомагнитный доступ | минуты витка, когда магнитное поле Земли пропускает протоны к станции; их знают заранее по траектории и прогнозу индекса бури Kp |
| экспозиция | минуты доступа, когда протоны от 30 МэВ доходят до станции |
| момент отсечения | момент в прошлом, из которого строится прогноз; более поздние данные расчёт не видит |
| реконструкция, «факт» | тот же расчёт той же моделью по данным, опубликованным позже, а не независимое измерение |
| простой подход (бейзлайн) | способ попроще, с которым мы сравниваемся в «Прогнозе из прошлого» на странице и в выгрузке: последнее измерение, последнее готовое предупреждение или прогноз SWPC (центр космической погоды NOAA) без привязки к орбите |
| попадания, пропуски, ложные тревоги | счёт опасных минут: предсказали, и она была; была, но не предсказали; предсказали, а не было |

Режимов три:

| режим | зачем | что видит расчёт |
|---|---|---|
| «Сейчас» | текущая обстановка и ближайшие окна | живые данные источников |
| «Разбор по архиву» | разбор прошедших дат | всё, что доступно сегодня, включая поздние уточнения |
| «Прогноз из прошлого» | проверка: что сервис сказал бы тогда | только данные, опубликованные до момента отсечения; потом ответ сверяется с реконструкцией |

## Что умеет

- Считает два механизма риска: солнечные протоны на минутах геомагнитного доступа и метеорные потоки по почасовому
  коэффициенту усиления (годовые прогнозы NASA MEO для низкой орбиты). Ещё показывает сближения с объектами на
  орбите (в режиме «Сейчас»), прокси дозы среды (не дозу человека), освещённость и геометрию доступа протонов.
- Перебирает окна той же длительности в периоде допустимого начала (до 24 ч) с шагом 15 минут. Называет
  предпочтительное окно и причину обычными словами или объясняет, почему выбрать нельзя. Окно с пробелом данных не
  выбирается.
- Работает на любые даты: архив за недостающие сутки скачивает сам при первом расчёте, а где архива нет, называет
  пробел.
- Пишет сводку для экипажа и отвечает на вопросы, текстом и голосом. Языковая модель только формулирует. Каждое
  число в её тексте сверяется с расчётом, без модели ответ собирается по шаблону из тех же фактов.
- Отдаёт zip-выгрузку: ответ в JSON, отчёт в Markdown, таймлайн в CSV и список источников.

## Запуск

### Docker

Нужны Docker с Compose v2 и свободные порты 80 и 443. Доступ к репозиторию выдают организаторы.

```sh
git clone https://gitverse.ru/hackrus.experts/kosmo-piter_misis_go_15.git
cd kosmo-piter_misis_go_15
cp .env.example .env    # вписать любой POSTGRES_PASSWORD
make up                 # Postgres, API, воркер, Caddy
```

Страница откроется на http://localhost/. Логи: `make logs`, остановка: `make down`.

### Без Docker

Нужны Python 3.12, [uv](https://docs.astral.sh/uv/) и [Bun](https://bun.sh/).

```sh
cp .env.example .env
make sync                          # зависимости Python
make front                         # сборка страницы
scripts/dev_server.sh start        # API и страница на http://localhost:8000/ (порт вторым аргументом)
scripts/dev_server.sh worker-start # воркер: расчёты и опрос источников
```

Сервер, данные, языковая модель, озвучка и логи: [docs/DEPLOY.md](docs/DEPLOY.md).

### Первый расчёт

1. В разделе «Планирование ВКД» выберите пример «Прогноз из прошлого: 11 мая 2024, отсечение 10 мая 12:30» и
   нажмите «Рассчитать».
2. Первый расчёт на новый период скачивает архив этих суток, это около 2 минут. Повторные занимают секунды.
3. В ответе будут рекомендация с причиной, таймлайн по линиям, сводка для экипажа и блок «Проверка после события»
   с тремя простыми подходами.

Готовить данные заранее не нужно, интернет нужен воркеру.

## Как это работает

Воркер это фоновая часть сервиса: он опрашивает источники и выполняет расчёты. Данные идут так:

```
 NOAA SWPC и NCEI · NASA (эфемерида МКС, DONKI, прогноз метеоров MEO) · GFZ Kp · CelesTrak
        │  воркер: опрос по расписанию и докачка архива под запрошенный период
        ▼
 сырое хранилище: файлы байт в байт, у каждого время публикации и версия
        │  AsOf(T): расчёт видит только то, что было опубликовано к моменту T
        ▼
 трасса МКС по эфемериде NASA ──► линии риска поминутно по трассе ──► сравнение окон
                                                                          │
                                                                          ▼
                             рекомендация с причиной · сверка с фактом · сводка для экипажа
                                                                          │
                                                                          ▼
                                                  страница · API · выгрузка zip
```

### Как мы считаем протоны

Солнечное протонное событие опасно для выхода не всё время, а только на минутах геомагнитного доступа. Мы считаем
протоны от 30 МэВ: они проходят все части скафандра (Leske et al. 2001). До станции они доходят, когда её магнитная
широта выше широты обрезания. В спокойное время это 63.4° по фиту измерений спутника SAMPEX (Ogliore et al. 2001,
сверено с Leske et al. 2001). В бурю граница опускается к экватору, и мы сдвигаем её по индексу Kp на 0.92° за
единицу (Leske et al. 2001; Smart & Shea 2003).

Уровень зависит от того, открыт ли доступ (поток меряют в pfu, единицах потока частиц):

| где станция | уровень | основание |
|---|---|---|
| закрыта магнитным полем | не выше `elevated` при любой буре | шкала S, пять ступеней протонной бури (NOAA Space Weather Scales), описывает обстановку на геостационарной орбите, а не у станции |
| в доступе, поток от 30 МэВ не ниже 1 pfu | `high` | наше правило по аналогии с порогом ESPE |
| в доступе, поток от 100 МэВ не ниже 1 pfu | `critical`, окно исключается | порог события для экипажа ESPE (NASA SRAG 2020) |

Поэтому даже во время события внутри суток находятся окна без опасных минут, как 11 мая 2024. Линии, пороги и
правила сравнения окон описаны в [docs/MODEL.md](docs/MODEL.md).

## Результаты

Таблицы, условия и разбор лежат в [docs/RESULTS.md](docs/RESULTS.md). К цифрам ниже две оговорки:

- «Факт» в проверке это реконструкция нашей же моделью по данным, опубликованным позже, а не независимое
  измерение. Ошибку самой модели доступа такая проверка не поймает.
- Правила выбора окна мы настраивали на сутках 11 мая 2024, порог метеоров на сутках 13 июня 2024. На этих датах
  проверка не независима. Что на каких датах настраивалось, перечислено в начале
  [RESULTS.md](docs/RESULTS.md#что-настраивалось-на-каких-датах).

| проверка | итог |
|---|---|
| Прогноз из прошлого на 11 мая 2024, момент отсечения 10 мая 12:30 | Предупреждение за 13 ч 48 мин до первых опасных минут. По минутам 93 попадания, 14 пропусков и 18 ложных тревог. Перенос на 09:30–15:30 совпал с окном по реконструкции. |
| Три простых подхода на тех же данных | Оставляют запрошенное окно 04:00–10:00, где по реконструкции 74 минуты экспозиции, а наш расчёт выбирает окно без них. Ноль попаданий у простых подходов заложен построением: два не выдают `high`, а «последнее измерение» видит отсчёт давностью 6.5 суток. |
| Устойчивость к модели границы доступа, 11 мая | По Kp 9, как в сервисе, и по двум формулам через индекс бури Dst (Birch et al. 2005; Leske et al. 2001) минут доступа в окне 09:30–15:30 выходит 0, 2 и 50, в запрошенном окне 76, 86 и 144. Перенос устойчив, но ноль в новом окне держится только на модели по Kp. |
| 8 июня 2024 | Вспышка случилась после момента отсечения, и её 32 опасные минуты пропустили все подходы. Сервис прямо пишет, что поток не измерен. |
| Спокойные сутки 13 июня 2024 | Ложных тревог по протонам нет. |
| Восемь прогнозов на 2024–2025 | Без событий, по которым выбраны сроки удержания (сколько событие считается идущим после последнего сообщения о нём): 183 минуты попаданий, 63 пропуска, 24 ложные тревоги. Все 183 попадания пришлись на 11 мая 2024. |
| Чувствительность: 75 значений параметров без первоисточника | Параметры меняли по одному на трёх расчётах из мая–июня 2024. Окно меняется в 10 случаях. |
| Приёмочные проверки | 10 из 10, среди них утечка будущего, отказ источников и граничные даты. |

Линия метеоров в мае–июне 2024 выбор окна не меняла. Коэффициент усиления по годовому прогнозу NASA MEO не
поднимался выше 0.33, а порог `high` у нас 5.0. Метеоры мы считаем фактором планирования, а не количественной
оценкой риска для экипажа.

## Честность данных

- У каждой сырой записи есть время публикации, и прогноз из прошлого берёт только опубликованное до момента
  отсечения.
- Нет данных значит «нет данных», а не «спокойно». Отказ источника виден на странице, а наблюдение, внешний прогноз
  и наш расчёт помечены по-разному.
- Что взято из литературы и стандартов, а что наше правило, разобрано в
  [docs/SCIENTIFIC_BASIS.md](docs/SCIENTIFIC_BASIS.md).
- Два параметра из литературы человек пока не проверил: коэффициент поправки широты обрезания по Kp и порог
  Южно-Атлантической аномалии (Heirtzler 2002). Они помечены в каждом результате.
- В каждом ответе есть версия алгоритма: sha кода и хеш конфигов.

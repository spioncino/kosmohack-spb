# Библиотеки, модели и справочные данные: роль и версии

Постановка разрешает готовые библиотеки, предобученные и языковые модели, если указаны их роль и версии. Здесь мы
перечисляем прямые зависимости сервиса и страницы, все модели и справочные таблицы, на которых стоит расчёт.

## Коротко

Сервер написан на Python 3.12. API держится на FastAPI, расчёты на numpy, а орбиту и магнитное поле считают
skyfield, aacgmv2 и ppigrf. Задания и состояние источников лежат в базе: PostgreSQL в Docker, SQLite без него.

Страница написана на Vue 3 и TypeScript, собирает её Vite. Трёхмерная сцена сделана на three.js. Где станция сейчас,
браузер считает сам через satellite.js.

Моделей три, и ни одну мы не обучали. Qwen 3.8 только формулирует сводку для экипажа. Silero TTS `v4_ru` по желанию
её озвучивает. Распознавание речи браузера позволяет задать вопрос голосом.

Из справочных данных расчёт берёт коэффициенты магнитного поля, прогнозы метеорных потоков NASA, таблицы ICRP 116 и
NIST PSTAR для прокси дозы. Страница добавляет контуры суши для карты.

Все версии закреплены lock-файлами, и тест при каждой проверке сверяет с ними таблицы этого документа.

## Несколько слов

- Прямая зависимость: библиотека, которую подключаем мы сами. Транзитивная: та, что нужна другой библиотеке.
- Lock-файл: список точных версий всех библиотек, прямых и транзитивных. По нему на любой машине ставится ровно то
  же самое.
- Предобученная модель: нейросеть, которую уже обучил её автор. Мы её только скачиваем или вызываем.
- Языковая модель: предобученная модель, которая пишет текст по запросу.

## Как закреплены версии

Версии Python-пакетов записаны в `uv.lock`, пакетов страницы в `frontend/bun.lock`. Транзитивные зависимости
закреплены там же.

- `uv sync --frozen` ставит ровно версии из `uv.lock`. Это первая команда `make sync` и стадия builder в
  `Dockerfile`.
- `bun install --frozen-lockfile` делает то же по `frontend/bun.lock` в `make front` и на стадии frontend-deps.
- Тест `tests/unit/test_deps_check.py` сверяет четыре таблицы пакетов ниже с `pyproject.toml`, `uv.lock`,
  `frontend/package.json` и `frontend/bun.lock`. Пакет без строки, строка без пакета или другая версия роняют
  `make check`.

Интерпретатор Python 3.12 (`requires-python` в `pyproject.toml`, `.python-version`). Образы Docker:
`python:3.12-slim` для сервиса, `oven/bun:1` для сборки страницы, `postgres:16` для базы и `caddy:2` для веб-сервера
на входе, который слушает порты 80 и 443.

## Модели

Все три модели обучили их авторы, мы их только подключаем.

| модель | версия | роль | обучение командой |
|---|---|---|---|
| Qwen 3.8 в облаке Cloud.ru Evolution, API совместимый с OpenAI | имя развёртывания в API задаёт переменная `QWEN_MODEL` (значение по умолчанию в `briefing/llm.py` и `.env.example`); температура 0.2, до 300 токенов, тайм-аут 20 с; веса и их обновления на стороне провайдера | Только формулирует сводку для экипажа (D58) по списку фактов, а список собирается из готового расчёта без модели. Каждое число, время и дата в тексте сверяются со списком (`briefing/validate.py`). Нарушение даёт одну повторную попытку, дальше шаблон из тех же фактов; без ключей всегда шаблон. На расчёт, уровни и рекомендацию модель не влияет. В ответе сводки есть поля `source` (`llm` или `template`) и `model` | нет, не обучалась и не дообучалась |
| Silero TTS | `v4_ru`, файл `https://models.silero.ai/models/tts/ru/v4_ru.pt`, 40 107 184 байт | Синтез речи в необязательной службе `tts/` (`make up-voice`). Озвучивает `speech_text` сводки, текст без цифр и латиницы, в WAV 48 кГц. Без службы озвучивает сам браузер. Лицензия моделей Silero CC BY-NC-SA 4.0, только некоммерческое использование (`tts/README.md`) | нет |
| Распознавание речи браузера (Web Speech API, `SpeechRecognition`) | не закреплена: модель и службу выбирает браузер; в Chrome облачный сервис Google, в Edge сервис Microsoft, в Firefox API нет | Голосовой ввод своего вопроса в сводке для экипажа (D90), `frontend/src/lib/voiceInput.ts`: одна фраза на русском попадает в поле вопроса. Звук уходит из браузера в его службу распознавания, на сервер evarisk звук не передаётся, страница получает только текст | нет |

sha256 копии модели Silero в `data/tts/v4_ru.pt` на машине разработки:
`896ab96347d5bd781ab97959d4fd6885620e5aab52405d3445626eb7c1414b00`.

Служба `tts/` живёт в своём окружении, чтобы тяжёлый torch не попал в основной образ. Её пакеты перечислены в
`tts/requirements.txt` и `tts/Dockerfile`: torch из индекса CPU `https://download.pytorch.org/whl/cpu`, numpy,
fastapi, `uvicorn[standard]`. Версии там не закреплены, и образ `evarisk-tts` ставит последние на момент сборки. На
машине разработки в `tts/.venv` стоят torch 2.14.0+cpu, numpy 2.5.3, fastapi 0.141.1, uvicorn 0.53.0.

Мы не обучали и не дообучали ни одной модели, поэтому состав и период обучающих данных не указываем (R18 в
`docs/REQUIREMENTS.md`). Правила окон и пороги линий детерминированы, это формулы, а не обученная модель. Параметры
для них взяты из стандартов и литературы, у каждого есть источник. Собственные правила так и названы собственными.
Где это посмотреть: [SCIENTIFIC_BASIS.md](SCIENTIFIC_BASIS.md), раздел «Параметры и их источники» в
[MODEL.md](MODEL.md), поля источников в `config/*.toml`.

Одно исключение подобрано по данным. Сроки удержания события DONKI (D60, D64) мы выбрали по длительностям трёх
событий вне тестового периода. Об этом сказано в R18 и в [INDEPENDENT_PERIODS.md](INDEPENDENT_PERIODS.md).

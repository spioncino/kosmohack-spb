# replay

Назначение: сверка прогноза из прошлого с фактом и сравнение с тремя бейзлайнами на том же отсечении (D66). Модуль читает данные только через `AsOf`, ничего не подставляет вместо отсутствующих данных и никогда не меняет рекомендацию (D5).

## Интерфейс
- `verify.Verification(Frozen)`: `truth_asof` всегда `None` (факт это `AsOf(store, None)`), `line` (`sep_protons`), `predicted` и `observed` интервалы, `observed_availability`, `observed_preferred`, `observed_insufficient`, `lead_time_minutes`, `first_observed_alarm`, `first_predicted_warning`, `hit_minutes`, `miss_minutes`, `false_alarm_minutes`, `quiet_minutes`, `unverified_minutes`, `predicted_unknown_minutes`, `window_choice_stable`, `note`; счёты экспозиции `exposure_hit_minutes`, `exposure_miss_minutes`, `exposure_false_alarm_minutes`; `requested_exposure_minutes` и `preferred_exposure_minutes`, минуты экспозиции экипажа по факту в запрошенном и предпочтительном окне; `baselines`, кортеж `BaselineCheck` (D66).
- `verify.verify(result, store) -> Verification`: для результата режима `replay` повторяет шаги `run_assessment` режима review с `AsOf(store, None)` (OEM по доступности, линия SEP, линия метеоров, линия освещённости на траектории факта, окна-кандидаты и запрошенное окно с ограничениями запроса `constraints`, рекомендация по тем же правилам) и сравнивает интервалы линии `sep_protons` по минутам периода поиска. Вызывается из `api.service.run_assessment` при `mode == replay`; результат в поле `AssessmentResult.verification`.
- `verify.compare(cutoff, predicted, observed, span, *, predicted_preferred, observed_preferred, observed_insufficient, observed_availability, line, notes) -> Verification`: чистая функция над интервалами (D41). Минута периода поиска считается попаданием при «предсказано ≥ high и наблюдено ≥ high», ложной тревогой при «предсказано ≥ high, наблюдено ниже», пропуском при «наблюдено ≥ high, предсказано ниже или без уровня», спокойной при «оба ниже high»; минута без факта (`unknown` у наблюдения) это `unverified`, минута без уровня прогноза дополнительно считается в `predicted_unknown`. Заблаговременность это минуты от `cutoff` до первого наблюдённого интервала ≥ high в периоде при условии, что прогноз дал `elevated`, `high` или `critical` не позже этого момента; иначе `None` с причиной в `note`. `window_choice_stable` истинно, когда окно прогноза совпало с окном по факту или входит в число равнозначных ему по факту (`observed_equivalents`, D65); оба `None` тоже совпадение.
- `verify.minute_counts`, `verify.first_start`, `verify.level_at`: помощники сравнения, минута вне интервалов это `unknown`.
- `verify.BaselineCheck(Frozen)`: `name`, `title`, `rule`, `level` (наибольший названный уровень), `basis`, `provenance`, `preferred`, `insufficient`, `preferred_exposure_minutes` (главный показатель: минуты экспозиции по факту в окне, которое выбрал бейзлайн), `exposure_hit_minutes`, `exposure_miss_minutes`, `exposure_false_alarm_minutes` (бейзлайн с уровнем ≥ high называет экспозицией каждую минуту), `lead_time_minutes`, `window_choice_stable`, `note`; без факта числа `None`.
- `verify.baseline_checks(result, store, truth)`: три бейзлайна на отсечении расчёта с линиями метеоров и сближений расчёта (кроме `unusable_for_replay`) и ограничениями запроса; отказ бейзлайна не отменяет расчёт, причина пишется в `note`. `verify.exposure_in(observed, window)`: минуты экспозиции факта внутри окна.
- `baseline.Baseline(Frozen)`: `name`, `title`, `level`, `basis`, `provenance`, `line` (одна `LineAssessment` `sep_protons` с одним интервалом на весь период поиска, `kind=computed`), `windows`, `recommendation`.
- `baseline.persistence(req, store, *, cfg=None, rules=None, other_lines=()) -> Baseline`: уровень по шкале S (`risk.lines.sep.env_level`) последнего доступного на момент `cutoff` отсчёта p10 (поиск не дальше 48 ч назад, потому что суточные файлы GOES доступны на следующие сутки, D19/D22) распространяется на весь период поиска; без отсчёта `unknown` и `availability=missing`. Доступ частиц по траектории не учитывается.
- `baseline.single_alert(req, store, *, rules=None, other_lines=()) -> Baseline`: последнее на момент `cutoff` утверждение о шкале S: строка «over the past 24 hours, was above|below S-scale storm level thresholds» последнего выпуска `swpc_archive/3day_forecast` (регулярное выражение здесь, а не в `parsers/`) или сообщение `donki/notifications` типа SEP с «GOES … > 10 MeV protons exceeds 10 pfu», датированное по `messageIssueTime` (через `AsOf.aggregates`); S ≥ 1 даёт `elevated` всему периоду, иначе `none`; без утверждений `unknown`. У сообщения DONKI нет отбоя, давность утверждения пишется в `basis`.
- `baseline.swpc_outlook(req, store, *, cfg=None, rules=None, other_lines=(), illumination=None) -> Baseline`: вероятность протонного события S1+ на каждые сутки периода из последнего на момент `cutoff` выпуска `daypre` или 3-day forecast (`store.views_kp.proton_event_probability`, то же основание, что у линии SEP за горизонтом персистентности, D42); не ниже `proton_outlook_threshold_percent` даёт `elevated` суткам, ниже `none`, сутки без выпуска `unknown`; интервалы `external_forecast`, по одному на сутки. Траектория не учитывается: бейзлайн показывает, что даёт привязка прогноза к виткам.
- Все три бейзлайна принимают `illumination` и ранжируют окна с ограничениями запроса (`req.constraints`).
- Окна у бейзлайнов ранжируются теми же `windows.compare` по линии бейзлайна вместе с `other_lines` (в эксперименте это линия метеоров того же replay-расчёта), сверка с фактом той же `verify.compare`.
- `scripts/run_experiments.py`: три периода (события 10–12 мая и 8 июня 2024, контрольные сутки после 12 июня по Kp GFZ ≤ 3, официальному списку и GOES), вывод `docs/experiments/*.json` и `README.md`.

## Инварианты
- Бейзлайны видят только данные до отсечения (`AsOf(store, cutoff)`); это проверяет `tests/e2e/test_replay_verification.py::test_replay_compares_three_baselines_on_the_same_cutoff`.
- Сверка хранится отдельно в `result.verification` и не участвует в рекомендации; в `note` всегда есть ссылка на D41 и D5.
- Факт ранжирует окна по тем же правилам, что расчёт: `windows.compare.score` с `constraints` запроса и линией `illumination` (`risk.lines.illumination.IlluminationLine`) на траектории факта. Поэтому `observed_preferred` и `window_choice_stable` сравнивают выбор по одному правилу (D43); бейзлайны берут освещённость из результата расчёта и те же `constraints`.
- Окна со стартом раньше отсечения исключаются и в факте (`observe`), и в бейзлайнах (`baseline._rank`) с той же причиной «окно начинается раньше момента отсечения», что в расчёте (D80): прогноз, факт и бейзлайны сравниваются на одном наборе окон.
- Факт без данных (`missing`/`stale`) остаётся непроверяемыми минутами, а не «спокойно».
- Внешний прогноз в `predicted` остаётся `external_forecast`, факт всегда `computed`: сравниваются уровни, а не источники.

## Как тестировать
- `uv run pytest tests/unit/test_verify.py -q`: синтетические интервалы с минутами, посчитанными вручную.
- `uv run pytest tests/unit/test_baseline.py -q`: прогноз SWPC без орбиты при отсечении 10 мая 12:30 берёт 55 % выпуска 12:30, при 06:00 50 % выпуска 00:30 (порог включителен), сутки без выпуска `unknown`. Фикстуры GOES 10 мая (доступен с 11 мая 00:05), 3-day forecast 10 мая и DONKI 9–12 мая: персистентность при отсечении 10 мая 12:30 это `missing`, при 11 мая 02:00 отсчёт 23:55 не ниже S1; единственное предупреждение при 10 мая 12:30 это `none` («below»), при 11 мая 02:00 `elevated` по DONKI 20240510-AL-005.
- `EVARISK_RAW_ROOT=… EVARISK_ASSESSMENTS_ROOT=… uv run python scripts/run_experiments.py` пересобирает `docs/experiments/`.
- Ограничения освещённости в сверке (`tests/e2e/test_replay_verification.py`): при `start_in_daylight` и старте 11 мая 13:15, который по траектории факта в тени, каждое окно факта со стартом в тени исключено с «ограничение освещённости: старт в тени», предпочтительное окно факта не запрошенное и начинается на свету, `window_choice_stable` считается по окнам факта с тем же ограничением. При `min_sunlit_fraction` 1.0 и окне 2 ч (виток МКС около 93 мин, в каждом окне есть минуты тени) выбора нет ни в расчёте, ни по факту, ни у бейзлайнов, и `window_choice_stable` истинно: оба выбора пусты.
- `uv run pytest tests/e2e/test_replay_verification.py -q`: хранилище conftest плюс файл GOES 11 мая, выпуски SWPC 10 мая и DONKI; отсечение 2024-05-10T19:00Z (эфемерида фикстуры создана 18:51:53), окно 11 мая 04:00 +6 ч, период 00:00–14:00: прогноз `elevated` по вероятности S1 55 %, факт содержит `critical`, попаданий 0, пропуски > 0, ложных тревог 0, заблаговременность между 430 и 579 мин (событие 11 мая 02:10 по официальному списку, critical с 04:39 по risk/README.md).

## Чего не делать
- Не менять рекомендацию по результату сверки и не подмешивать факт в прогноз.
- Не считать минуту без факта спокойной.
- Не читать хранилище мимо `AsOf`.

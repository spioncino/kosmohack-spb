# Правила разработки evarisk

Здесь собраны правила, по которым мы пишем evarisk, сервис для выбора окна выхода в открытый космос. За ними стоят
три идеи. Нет данных не значит «спокойно». Каждое число можно проверить по сырой записи. Прогноз из прошлого не
видит будущего.

Дизайн системы: `docs/design/2026-09-18-eva-risk-system-design.md`. Критерии жюри: `docs/CRITERIA.md`.

## Порядок изменения

1. Прочитать `README.md` модуля, строку задачи в `docs/TASKS.md` и её критерии в `docs/CRITERIA.md`.
2. Новое решение сначала записать в `docs/DECISIONS.md`.
3. Сначала тест на реальной фикстуре из `tests/fixtures/`, то есть на сохранённом файле источника, потом код.
4. `make check` зелёный.
5. Обновить строку модуля в `docs/STATUS.md`. Если поменялся интерфейс, обновить и `README.md` модуля.
6. Сообщение коммита: `<модуль>: <что сделано> [T3,O2]`, где в скобках критерии из `docs/CRITERIA.md`.

## Что проверяет `make check`

Быструю версию этой проверки перед каждым коммитом запускает хук, его ставит `make hooks`.

1. Комментарии только констатируют факт. Обращения к читателю, TODO и FIXME запрещены: задачи живут в
   `docs/TASKS.md`.
2. Отсутствие данных это `Availability`/`None`, никогда 0, `NaN` или пустая строка «по умолчанию». Ноль читался бы
   как «спокойно».
3. Все даты tz-aware UTC, то есть с явным поясом. `datetime.now()` без `tz` и `utcnow()` запрещены.
4. Модули `risk/`, `windows/`, `orbit/`, `replay/` читают данные только через `AsOf`, не через таблицы. `AsOf`
   отдаёт только записи, опубликованные к моменту расчёта, поэтому прогноз из прошлого не видит будущего.
5. Коммит, меняющий код модуля, обновляет его строку в `docs/STATUS.md`. У каждого модуля есть `README.md`.
6. Тесты не ходят в сеть. Ожидаемые значения берутся из документов и физики, не из вывода кода, иначе тест
   подтвердит и ошибку.

## Что смотрим на ревью

- Наблюдение, внешний прогноз и наш расчёт различаются всегда: поле `kind`.
- Каждое число в ответе имеет `Provenance` с `raw_id`, ссылкой на сырую запись. Нет провенанса, нет числа.
- Внешний прогноз не выдаётся за наш. Связанные сигналы одного события не суммируются, чтобы не учесть его дважды.
- Отказ источника не превращается в «обстановка благоприятная».
- Секреты только в `.env` и `.env.llm`. Данные Space-Track не коммитятся: этого требует их пользовательское
  соглашение (D13).

## Команды

| команда | что делает |
|---|---|
| `make sync` | ставит зависимости |
| `make check` | полная проверка |
| `make check-fast` | быстрая проверка |
| `make hooks` | ставит хук с быстрой проверкой перед коммитом |
| `make fetch [START=2025-11-01 END=2025-11-13]` | докачивает зеркало архивов за период и импортирует его в `data/raw` |
| `uv run pytest tests/unit -q` | только юнит-тесты |

## Карта

Код сервиса лежит в `src/evarisk/`:

| путь | что там |
|---|---|
| `types.py` | ядро типов |
| `timeutil.py` | время |
| `config.py` | настройки из окружения |
| `store/` | сырое хранилище и индекс |
| `sources/` | адаптеры источников |
| `parsers/`, `orbit/` | разбор форматов |
| `risk/` | линии риска |
| `windows/` | сравнение окон |
| `replay/` | отсечение и сверка |
| `export/` | выгрузка |
| `api/` | FastAPI |
| `worker/` | планировщик и задания |
| `briefing/` | сводка для экипажа |

В корне проекта: `web/` мини-фронт, `frontend/` рабочее место аналитика, `tts/` локальный синтез речи, `scripts/`
служебное. Документы: `docs/STATUS.md` что сделано, `docs/TASKS.md` доска задач, `docs/DECISIONS.md` решения,
`docs/SOURCES.md` источники.

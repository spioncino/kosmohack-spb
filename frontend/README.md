# MISIS GO: интерфейс оценки внешних рисков ВКД

Рабочее место аналитика группы планирования внекорабельной деятельности на МКС поверх API `evarisk`
(`src/evarisk/api`). Интерфейс показывает интервалы уровней по линиям риска, сравнение окон одинаковой
длительности, рекомендацию или объяснение, почему оснований нет, происхождение каждого числа и состояние
источников. Допуск к ВКД принимают уполномоченные специалисты; интерфейс не выдаёт разрешений.

Стек: Bun, Vite, TypeScript, Vue 3, Vue Router (hash-история), Vitest, Three.js, satellite.js, world-atlas, marked.

## Запуск

```sh
cd frontend
bun install
bun run dev        # http://localhost:4173, пути API проксируются на http://localhost:8000
bun run build      # vue-tsc --noEmit и vite build в dist/
bun run test       # vitest
```

Адрес API для dev-прокси задаётся переменной `EVARISK_API_URL` (по умолчанию `http://localhost:8000`).
Рядом должны быть запущены `make api` и `make worker`: без воркера задания остаются в очереди, и это видно
в интерфейсе. Собранный `dist/` раздаётся FastAPI как статика на `/`.

Браузер не делает внешних запросов: все данные приходят из API, положение станции считается в браузере
по OMM из `GET /orbit/latest` через satellite.js (SGP4), трасса берётся из `GET /trajectory` или из
траектории открытого расчёта. Исключение одно: голосовой ввод своего вопроса (D90) распознаёт речь средствами
браузера, и в Chrome звук уходит в облачный сервис Google (в Edge в сервис Microsoft). Это запрос самого браузера,
а не страницы; на сервер evarisk звук не передаётся, уходит только текст вопроса после «Спросить».

| `/eva` | форма запроса (режим, отсечение, начало и длительность ВКД, период допустимого начала: начало и длина до 24 ч, ограничения освещённости), прогресс задания по шагам, баннер «Результат относится к предыдущим параметрам» или «Идёт новый расчёт» над прежним результатом, баннер «изменение плана» над рекомендацией, рекомендация, запрошенное окно, таймлайн интервалов по линиям с бейджами `kind`, сверка с фактом для replay и в ней таблица «Сравнение с простыми подходами» (наш расчёт и бейзлайны: предсказанный уровень и основание, выбранное окно, экспозиция по факту в нём, попадания, пропуски и ложные тревоги по минутам экспозиции, заблаговременность, устойчивость окна), ограничения | `POST /jobs`, `GET /jobs/{id}`, `GET /assessments/{id}`, `GET /orbit/latest` (конец покрытия эфемериды для проверки дат режима «сейчас») |

| `/sources` | таблица источников, состояние, причина, давность, ошибки; заморозить, отключить, активировать с причиной; обновить с ожиданием задания | `GET /sources`, `POST /sources/{name}/state`, `POST /sources/{name}/refresh`, `/health` |

## Правила интерфейса

- Оценка фактора (`src/lib/score.ts`, обзор «Оценка факторов» и вкладки `/risks`) показывает плашку «в запрошенном
  окне: N мин high+critical»; вкладки `/risks` показывают над ней процент P, долю периода поиска без
  high/critical (подпись процента во всплывающей подсказке, на обзоре процента нет). Процент считается по всему периоду поиска, округляется вниз и на цвет не влияет. Минуты окна берутся из
  часов `requested_window.per_line[линия]`, а для линии, которой там нет, из интервалов линии на отрезке
  `requested_window.window` (без него `request.eva_start` + `duration_hours`). Цвет плашки по запрошенному
  окну: красная, если в окне есть `high` или `critical`; жёлтая, если в окне есть `elevated` или `unknown`,
  часть окна не покрыта интервалами, полнота периода поиска ниже 99,9 %, поток линии не измерен хотя бы одну
  минуту периода (`metrics.unmeasured_minutes` больше нуля, D64) или окно не определено; зелёная, только если в
  окне один `none` при полных измеренных данных; серая при `availability` не `available`, даже если в окне есть
  часы: подпись «нет архива за эти даты» при `unusable_for_replay` (у источника нет архива, например SOCRATES для
  сближений в разборе и прогнозе из прошлого; это не поломка), «данные устарели» при `stale`, иначе «нет данных». Причина цвета одной фразой видна в подсказке и на карточке линии. Оценка ищется по имени
  линии; у геометрии доступа оценки нет, её вкладка подписана «без оценки».
- Неизмеренный поток (D82): при `metrics.unmeasured_minutes` больше нуля плашка не зелёная и не пишет «данные
  полные»; причина говорит «поток не измерен на N из M мин периода поиска, уровень взят из внешнего прогноза (в
  запрошенном окне K из L мин), а не из измерений», где K это минуты окна в интервалах `external_forecast`. На
  обзоре и на вкладке `/risks` фраза «поток не измерен: N из M мин периода, уровень по прогнозу» стоит во всплывающей
  подсказке строки и процента, видимой подписи под ними нет (по просьбе фронтенда подписи под строками убраны);
  рядом с «Полнота данных» на `/eva` и над таблицей `/compare` та же фраза и пояснение, что полнота считает минуты
  с уровнем, измерен он или взят из прогноза.
- Форма на `/eva` показывает ровно запрос открытого расчёта (`src/lib/requestForm.ts: formFromRequest`): режим,
  отсечение, начало и длительность ВКД, начало и длина периода допустимого начала (точно, без округления до шага
  поля) и ограничения. Открытие расчёта ставит выбранное время на его начало, и этот сдвиг форму не трогает; выбор
  другого времени в хедере или на карте по-прежнему двигает начало ВКД и период.
- Режим «сейчас» рассчитывает только ближайшие дни (D87, `src/lib/currentMode.ts: currentRangeIssue`): расчёт берёт
  эфемериду МКС, доступную на момент запроса и покрывающую период поиска с запасом в час, а текущий файл OEM NASA
  покрывает недавнее прошлое и две недели вперёд (файл от 18 сентября 2026: 18 сентября 12:00 – 3 октября 12:00 UTC). Если начало ВКД или периода поиска раньше суток до текущего
  момента, под началом ВКД сообщение «В режиме «Сейчас» доступны только ближайшие дни: для прошлых дат выберите
  «Разбор по архиву» или «Прогноз из прошлого»», кнопка «Рассчитать» недоступна, а кнопка «Переключить на разбор по
  архиву» меняет режим и оставляет даты. Если период поиска с часом запаса заканчивается позже `stop_time` последней
  эфемериды из `GET /orbit/latest`, сообщение называет конец покрытия; без этого поля будущее не проверяется.
  Насколько назад хватает старых эфемерид хранилища, API не отдаёт, поэтому граница прошлого сутки, как у переноса
  окна на ближайшие часы при выборе режима «сейчас» (он сохранён). Задание, которое всё же упало с
  `NoTrajectoryData`, показывает в панели прогресса понятную фразу с тем же советом (в разборе и прогнозе из прошлого
  про архив сервера), исходный текст ошибки во всплывающей подсказке (`components/ProgressSteps.vue`, `jobErrorText`).
- Прежний результат не выдаётся за текущий (D85). Если форма на `/eva` расходится с запросом показанного расчёта,
  над результатом крупный баннер «Результат относится к предыдущим параметрам: начало ВКД 2024-05-11 04:00 → 2024-06-08
  04:00» (что было → что в форме, коротко по каждому полю), а рекомендация, сводка для экипажа, запрошенное окно,
  таймлайн, сверка и ограничения приглушены. Сравнение в тех же терминах, что заполнение формы
  (`src/lib/requestForm.ts: formDifferences` против `formFromRequest`): времена как моменты UTC, длина периода
  допустимого начала в целых минутах, доля света числом (запятая как точка, пусто это «не задано»), отсечение только
  в прогнозе из прошлого. Пока идёт задание, поставленное пользователем, баннер «Идёт новый расчёт, ниже прежний
  результат» и то же приглушение; пришедший результат заменяет прежний, и баннер пропадает. Пересчёт автообновлением
  тот же запрос и баннера не ставит (`jobAuto` в `src/store/state.ts`). Возврат формы к запросу, вручную или кнопкой
  «Вернуть параметры расчёта», снимает баннер. На `/compare` то же по полю длительности: оно следует за открытым
  расчётом, а выбранная другая длительность до «Пересчитать» помечает таблицу окон как прежнюю. Текст баннера
  собирает `staleNotice`, компонент `components/StaleBanner.vue` (закреплён сверху при прокрутке результата).
- Автообновление (D82, `src/lib/refresh.ts`): открытый расчёт режима «сейчас» пересчитывается тем же запросом через
  задание, как по кнопке «Рассчитать», пока вкладка видна и задание не идёт: после новых данных источников
  (`last_success_at` активного источника позже `created_at` расчёта) не чаще раза в 5 мин, без них не реже раза в
  10 мин; после неудачной попытки повтор не раньше чем через 5 мин. Разбор и прогноз из прошлого не пересчитываются.
  На `/eva` строка «обновлено ЧЧ:ММ UTC · следующий пересчёт не позже …» и кнопка «Пересчитать сейчас», в хедере у
  открытого расчёта «обновлено ЧЧ:ММ UTC». Результат автообновления не сдвигает выбранное время, не пишется в архив
  браузера, не перезаписывает правки в форме (`autoRefreshedId`; при открытии экрана форма заполняется по расчёту всегда) и не открывается, если за время задания открыт
  другой расчёт.
- Факт в проверке после события это тот же расчёт по всем данным, доступным сегодня, включая опубликованные позже
  отсечения, а не независимые наблюдения: так он подписан в заголовке блока, строке и легенде таймлайна и подсказке
  окна по факту. Бейдж `kind` «наблюдение» у интервалов остаётся как есть.
- У каждого интервала бейдж `kind`: наблюдение, внешний прогноз, наш расчёт. У каждого числа есть ссылка на
  сырую запись (`GET /evidence/{raw_id}`), которая открывается в модальном окне.
- Период поиска задаёт допустимые моменты начала ВКД (глоссарий постановки). Форма на `/eva` спрашивает
  «Период допустимого начала (UTC)»: его начало и длину в часах (шаг 0,25, до 24). В запрос уходят
  `search_start` = начало периода и `search_end` = начало + длина + длительность ВКД (`src/lib/period.ts`).
  Проверка до отправки та же, что в API: отрезок от `search_start` до `search_end − duration_hours` занимает от
  15 минут (не меньше двух окон на сетке 15 минут) до 24 часов включительно, начало ВКД лежит в нём, границы
  включены. Три примера формы дают те же запросы, что посчитаны в документации: допустимое начало 4, 18 и 6 ч
  при 6 ч ВКД (периоды поиска 12:00–22:00, 00:00–24:00 и ближайшие 12 ч). Везде, где показан период открытого
  расчёта (шкала периода на обзоре, строка расчёта над картой, панели `/eva`, `/compare`, `/risks`, `/events`,
  `/objects`, архив), подпись «допустимое начало A–B · окна C – D», где B = `search_end − duration_hours`.
- Все времена в UTC с пометкой; `input[type=datetime-local]` трактуется как UTC (`src/lib/format.ts`).
- Ошибки API в формате `{"error": {"code", "message"}}` показываются текстом; отсутствие эфемериды (409)
  это ошибка, а не благоприятная обстановка.
- Если `GET /trajectory` недоступен, трасса строится по SGP4 из OMM и так и подписывается; освещённость,
  магнитная широта и ЮАА в этом случае «нет данных».
- В карточке запрошенного окна и в таблице сравнения минуты уровней подписаны обычными словами: «Опасные минуты
  (высокий и критический уровень)» (`high` и `critical`) и «Повышенный фон» (`elevated`), в целых минутах, а не в
  десятичных часах. Число окна это максимум по линиям, а не сумма (одна минута окна считается в каждой линии,
  сумма превышала бы длину окна); минуты каждой линии видны при раскрытии строки или в подсказке ячейки. Строки
  запрошенного окна по линиям: «протоны: опасные N мин, повышенный фон M мин, без данных K мин».
- Причины исключения окна (`excluded_reason`) в таблице сравнения и в карточке запрошенного окна показываются
  обычными словами (`src/lib/plain.ts: plainExclusions`): «критический уровень протонов: 26 мин», «нет данных:
  метеоры», «пробел данных: протоны, 225 мин», «мало света: на свету 95 % окна, задано не меньше 99 %», «старт в
  тени, а задан старт на свету». Незнакомый формат показывается как есть, запись сервера видна в подсказке.
- В replay над таблицей сверки одна строка-вердикт по полям `verification` (`src/lib/verdict.ts`); подписи
  полей объясняются в подсказках. Если равнозначных окон не меньше половины кандидатов, а линия протонов
  целиком одного уровня из внешнего прогноза, под заголовком рекомендации сказано, почему окна не различаются.
- Слова и значения с пунктирным подчёркиванием (бейджи уровня, `kind`, доступности и уверенности, подписи метрик
  на `/risks`, заголовки таблицы `/compare`, подписи сверки и таблицы бейзлайнов на `/eva`, поля формы «Отсечение» и
  «Период допустимого начала», слова объяснения рекомендации) открывают по щелчку или Enter пояснение из глоссария (`src/lib/glossary.ts`) со
  ссылкой «Подробнее в документации» на раздел `#/manual/<файл>#<якорь>`; Esc и щелчок вне окна закрывают. Тексты
  глоссария пересказывают документацию и не добавляют фактов. Внутри кнопки или ссылки слово показывается без
  пояснения, чтобы не перехватывать щелчок.
- Рекомендация на `/eva` и `/compare` читается обычными словами из `recommendation.explanation`
  (`src/lib/plain.ts: plainExplanation`): первое предложение это решение и заголовок («Рекомендуем перенести выход
  на 10:45–16:45 UTC, на 2 ч 15 мин раньше.»), остальные списком; строки по линиям («Протоны: в запрошенном окне
  4 ч 42 мин, в новом 2 ч 27 мин. …») после предложения с двоеточием в конце вложены в него, предложение о
  неизмеренном потоке выделено как предупреждение, фраза о линиях вне сравнения окон остаётся обычным пунктом.
  Понятия «опасные минуты», «повышенный фон», «повышенный», «высокий» и «критический уровень», «пробел данных» (и
  «пробел в данных»), «без данных», «не измерен», «равноценны» открывают пояснение глоссария у первого вхождения. Под объяснением одна
  фраза «Как выбирается окно: …» (`HOW_CHOSEN`), ниже свёрнутый блок «Технические подробности: правило выбора и
  коды решений» с технической записью и правилами сервера (`result.rules`). У расчётов без поля `explanation` (или
  с пустым списком) показывается техническая запись, как раньше; правила и тогда в свёрнутом блоке.
- Карточка «Окно для ВКД» на обзоре в строке «Обоснование» показывает кратко то же объяснение
  (`src/lib/plain.ts: plainBrief`, те же `PlainParts.vue` и `PlainList.vue`): решение и два следующих предложения,
  строки по линиям при своём предложении с двоеточием, пояснения терминов как на `/eva`. Ссылка «подробнее» ведёт
  на `/eva`, называет число непоказанных пунктов, а в подсказке держит техническую запись `reason`. У расчётов без
  `explanation` в карточке техническая запись, как раньше.
- Техническая запись причины (`src/lib/reason.ts`, `components/ReasonView.vue`): первая часть до «; » заголовком
  (предупреждение D64 о неизмеренном потоке выделено), остальные части списком, отрезки «04:36–04:50 sep_protons
  critical» метками «04:36–04:50 · протоны · critical», коды линий русскими подписями, коды решений ссылками на
  журнал решений. Слова причины не теряются и не добавляются. На `/eva` вместе с ней (`components/RecTechnical.vue`)
  строки предпочтительного окна по линиям «протоны: high+critical N мин, elevated M мин, без уровня K мин» из часов
  `per_line`, страховка по геометрии (D61) и число равнозначных окон.
- Коды решений D1…D72 в правилах, заметках интервалов, ограничениях и сверке ведут на строку журнала решений.
- Тень это условие работ, не событие: на экране событий и в ближайших событиях обзора интервалы освещённости
  скрыты, на экране событий есть переключатель «показывать тень».
- Сокращение или увеличение ВКД это изменение плана, а не улучшение при прежних условиях. Если новый расчёт
  отличается от открытого только длительностью (тот же режим, отсечение, начало ВКД, ограничения и период
  допустимого начала; конец периода поиска при этом сдвигается на новую длительность, как в `withDuration`), на
  `/eva` над рекомендацией и на `/compare` виден
  баннер «Изменение плана: длительность 6 ч → 4 ч» с предпочтительным окном и минутами high + critical в нём
  (максимум по линиям) для прежнего и нового плана и фразой, что окна сравниваются только внутри одной
  длительности (`src/lib/plan.ts`). Баннер скрывается кнопкой и снимается открытием постороннего расчёта.
- В replay под сверкой таблица «Сравнение с простыми подходами» (`src/lib/baselines.ts`): строка нашего расчёта
  (окно рекомендации, `verification.preferred_exposure_minutes`, попадания, пропуски и ложные тревоги по минутам
  экспозиции, заблаговременность, устойчивость окна) и по строке на бейзлайн из `verification.baselines`; главная
  колонка это экспозиция по факту в выбранном окне. Над таблицей подпись об одинаковых условиях сверки и строка
  «в запрошенном окне по факту: N мин экспозиции». Отсутствующее число это «нет данных», отсутствие окна «окна
  нет», неопределённая заблаговременность «не определена»; у расчётов без поля `baselines` или с пустым списком
  таблицы нет. Записи источников каждой строки открываются в панели записи.

## Устройство для разработчика

Назначение: рабочий интерфейс аналитика поверх API `evarisk` на Vue 3, TypeScript, Vite и Bun. Показывает
расчёт по линиям риска, сравнение окон, происхождение чисел и состояние источников; внешних запросов из
браузера нет.

### Интерфейс
- `api.*` в `src/api/client.ts`: `health()`, `sources()`, `setSourceState(name, state, reason)`,
  `refreshSource(name)`, `createJob(request)`, `job(id)`, `assessments()`, `assessment(id)`,
  `evidence(rawId)`, `briefing(id, question, voice, refresh)`, `briefingLatest(voice)`,
  `trajectory(start, end, stepMinutes, mode)`, `orbitLatest()`, `rules()`; ошибки
  поднимаются как `ApiError(status, code, message)` из тела `{"error": {...}}`; `waitJob(id, {onProgress})`
  опрашивает задание до `done` или `failed` раз в `POLL_MS`.
- `src/store/state.ts`: `selectedTime`, `setSelectedTime`, `assessment` (открытый расчёт),
  `runAssessment(request, {auto})` (`auto`: автообновление без сдвига выбранного времени и без архива),
  `openAssessment(id, focus = true)`, `autoRefreshState(now)` и `autoRefreshTick(now)` (срок и постановка
  автообновления расчёта «сейчас»; App.vue вызывает раз в 30 с и при возврате на вкладку), `autoRefreshAttempt`, `track` (сэмплы для сцены: расчёт, `/trajectory` или SGP4),

  постороннего расчёта) и `dismissPlanChange()`.

  начала), `windowsOf(result)` (запрошенное и рекомендованное окна, `moved`),

- Голосовой ввод своего вопроса (D90): `components/VoiceAskButton.vue` между полем и «Спросить», логика в
  `src/lib/voiceInput.ts` (`useVoiceInput`, `recognitionCtor`, `transcriptOf`, `voiceErrorText`). Web Speech API
  (`SpeechRecognition` или `webkitSpeechRecognition`, есть в Chrome и Edge, нет в Firefox), язык `ru-RU`, одна фраза
  (`continuous = false`): браузер сам завершает запись после паузы, кнопка «Стоп» останавливает раньше, страховка
  `VOICE_MAX_MS` 20 с. Текст по ходу речи и итоговый подставляется в поле (обрезается до 300 символов), фокус
  переходит в поле; вопрос отправляет пользователь кнопкой «Спросить» или Enter, автоматической отправки нет:
  распознавание ошибается в терминах и числах, и услышанный текст стоит прочитать до вопроса модели. Состояния:
  покой (микрофон), «слушаю» (красная точка, «Стоп» и строка «Слушаю: …» под полем), ошибка (перечёркнутый микрофон

- `src/lib/plain.ts`: `explanationOf(recommendation)` предложения `explanation` без пустых (нет поля → `[]`),
  `plainExplanation(recommendation)` заголовок, пункты с подпунктами по линиям и признак предупреждения (`null` без
  объяснения), `termParts(text, used)` части предложения с ключами глоссария (`PLAIN_TERMS`, слово в любом падеже,
  каждое понятие один раз), `plainExclusion(part)` и `plainExclusions(reason)` причины исключения по форматам
  `src/evarisk/windows/compare.py`, `minutesOf(hours)`, `HOW_CHOSEN`, `plainBrief(recommendation, limit = 2)`
  решение и первые `limit` пунктов для карточки обзора (`more` число непоказанных, `null` без объяснения). Тексты
  сервера не меняются: обычные слова показываются рядом с технической записью, а не вместо неё (на обзоре
  техническая запись в подсказке ссылки «подробнее»).
- Маршруты в `src/main.ts`, по одному компоненту в `src/views/`; общая оболочка в `App.vue`.

### Инварианты
- Все времена показываются в UTC с пометкой; поля `datetime-local` трактуются как UTC.
- Отсутствие данных это серое состояние «нет данных», не зелёное и не ноль.
- У каждого интервала виден `kind`; у каждого числа есть путь к записи `raw_id`.
- Тексты интерфейса без слов о прототипе и без заявлений о безопасности или допуске к ВКД.
- Карточка «Сводка для экипажа» показывает, кто сформулировал текст, и открывает факты с путём к записи;
  браузер только читает вслух готовый `speech_text`, ничего не пересказывая своими словами.
- Дизайн-токены в начале `src/style.css` не меняются; новые классы добавляются в конец файла.

### Как тестировать
- `bun run test` (Vitest, без сети); `bun run build` (`vue-tsc --noEmit` и `vite build`).
- Живая проверка: `make api`, `make worker`, `bun run dev`, открыть `http://localhost:4173`.

### Чего не делать
- Не обращаться к внешним сервисам из браузера; все данные через пути API из `vite.config.ts`.
- Не считать физику в браузере, кроме SGP4 по OMM для положения станции; уровни, освещённость и ЮАА только из
  ответов API.
- Не хранить результаты в localStorage: там только ссылки на расчёты сервера и идентификатор последнего.
